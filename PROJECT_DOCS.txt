  1. PROJECT OVERVIEW & VISION
================================================================================

  The AI Thumbnail Generator is a production-grade web application engineered
  exclusively for generating and editing high-CTR 16:9 YouTube thumbnails.

  Core Capabilities:
  ------------------
  (a) TEXT-TO-THUMBNAIL GENERATION
      The user enters a descriptive prompt for a video topic.
      Groq (Qwen 3.8 27B) enhances the prompt with professional thumbnail
      cinematography instructions, and the FLUX image engine renders a
      crisp 1280x720 (16:9) image.

  (b) IMAGE-TO-IMAGE EDITING
      The user uploads an existing thumbnail or reference photo via
      drag-and-drop and enters modification instructions (e.g. "Add neon
      glow and dark moody cyber background"). The AI regenerates the scene
      incorporating the modifications.

  (c) STRICT VISUAL INTENT GUARDRAIL
      The backend is protected by a 2-layer deterministic and keyword
      guardrail engine. Off-topic queries (coding, math, essays, translation)
      are immediately rejected with educational feedback before reaching AI models.

  (d) PERSISTENT GENERATION HISTORY (SUPABASE)
      Every generated thumbnail, prompt, model name, and storage path is
      saved to a Supabase PostgreSQL database. Users can view past generations
      in an interactive Gallery tab with a lightbox inspector.

  (e) CLOUD OBJECT STORAGE (AMAZON S3 & PRESIGNED URLS)
      Thumbnails are uploaded directly to a secure, private Amazon S3 bucket.
      Images are served to the browser via time-limited (24-hour) Presigned URLs,
      preventing public bucket exposure while supporting serverless scaling.

  7. PHASE 3 — AI IMAGE GENERATION ENGINE (GROQ QWEN + FLUX)
================================================================================

  Status: COMPLETED [x]

  Overview:
  Initially designed for Google Gemini/Imagen, the AI pipeline was upgraded to
  Groq's ultra-fast `qwen/qwen3.8-27b` for prompt engineering paired with the
  open FLUX model for photorealistic 16:9 thumbnail rendering.

  Why Groq API Instead of Google Gemini or Imagen?
  ────────────────────────────────────────────────
  1. 100% Free with Generous Usage Limits:
     - Groq offers high RPM (Requests Per Minute) and TPM (Tokens Per Minute)
       allowances on its free tier.
     - Unlike Google Cloud's Vertex AI / Imagen, Groq requires no complex GCP billing
       setup, no project quota increase requests, and no credit card billing locks.
     - The usage limits are more than generous to run the application, perform
       development testing, and serve real creators.

  2. Sub-300ms LPU Hardware Latency:
     - Groq's custom Language Processing Units (LPUs) execute open models like
       Qwen 2.5 / 3 in ~300 milliseconds.
     - Compared to Google Gemini (2.5s - 6.0s roundtrip), Groq makes thumbnail
       prompt expansion virtually instantaneous.

  3. Subject-Faithful Prompt Engineering & Eliminating AI Drift:
     - Early testing showed unconstrained LLMs can "hallucinate" unwanted subjects
       (e.g. turning a simple prompt "apple" into "a girl holding an apple in a cyber city").
     - We engineered a strict system prompt in `backend/app/ai_service.py` that:
       * Strictly preserves the user's primary focal subject verbatim.
       * Adds professional 3-point studio lighting, depth of field, and rim lights.
       * Only adds a human if the user explicitly requested a person/creator.
       * Appends strict quality tokens: `professional YouTube thumbnail, wide
         landscape format 16:9, cinematic photography, dramatic lighting, 4k`.

  How It Works:
  ─────────────
  1. Groq Prompt Engineering:
     - User input (e.g. "minecraft speedrun thumbnail") is processed through
       Groq's LLM using a specialized system prompt.
     - The LLM rewrites the concept into high-detail visual descriptions
       (composition, foreground focus, background depth, color temperature).

  2. FLUX Image Rendering:
     - The enhanced prompt is submitted to the FLUX rendering pipeline.
     - Enforces exact 1280x720 YouTube dimensions (`width=1280&height=720`).
     - Returns raw binary image bytes (JPEG).

  3. Image Editing Support (`/api/edit`):
     - Allows uploading an existing reference image (PNG/JPG/WEBP).
     - Groq adapts modification prompts to preserve focal subjects while
       altering backgrounds, lighting, and props.
     - Solved FastAPI 422 form parsing issue by annotating `prompt: str | None = Form(None)`
       and implementing fallback query string extraction.

  Files Modified/Created:
  - `backend/app/ai_service.py` — Prompt enhancement, FLUX rendering, output encoding.
  - `backend/tests/test_ai_service.py` — Mocked unit tests for generation/editing.

  11. PHASE 7 — AWS SERVERLESS BACKEND (AWS LAMBDA & API GATEWAY)
================================================================================

  Status: COMPLETED [x]

  Overview:
  Migrated the backend from running on a local host server (`localhost:8000`)
  into a fully serverless, auto-scaling architecture on AWS Lambda routed
  through Amazon API Gateway HTTP API.

  Key Concepts & Technology:
  ─────────────────────────
  1. What is AWS Lambda?
     - A serverless compute service that runs code only when triggered by events
       (like an incoming web request) and scales automatically to zero when idle.
     - You pay only for the compute time consumed (down to the millisecond).
     - Free Tier covers 1,000,000 free requests per month.

  2. What is Amazon API Gateway?
     - A managed HTTP/REST router that sits between the public internet and AWS Lambda.
     - Receives incoming requests (e.g. `POST /api/generate`) and forwards them
       as JSON event payloads directly to the Lambda function.

  3. What is Mangum?
     - An ASGI adapter that bridges FastAPI and AWS Lambda.
     - Translates API Gateway HTTP events into standard ASGI request scopes,
       passes them to FastAPI, and packages FastAPI's HTTP responses back into
       the API Gateway JSON format.
     - Handled via `handler = Mangum(app, lifespan="off")` in `backend/app/main.py`.

  Development & Deployment Steps:
  ───────────────────────────────
  1. Lightweight Lambda Production Packaging (`backend/package_lambda.py`):
     - Created `requirements-lambda.txt` omitting dev/local packages (uvicorn, pytest)
       and boto3 (which AWS pre-installs in the Lambda runtime).
     - Targeted Python 3.12 managed runtime on Amazon Linux (x86_64).
     - Used `pip install --platform manylinux2014_x86_64` to download Linux binary
       wheels on Windows for compiled packages (such as `pydantic-core`), preventing
       OS binary mismatch errors (`cannot import ELF/DLL`).
     - Compressed the entire backend into `backend/lambda_package.zip` (9.91 MB).
     - Uploaded build package to S3: `s3://ai-thumbnails-samrat-1234/builds/lambda_package.zip`.

  2. Automated Deployment Script (`backend/deploy_lambda.py`):
     - Automatically creates IAM Execution Role `ai-thumbnail-lambda-role`
       with `AWSLambdaBasicExecutionRole` and `AmazonS3FullAccess`.
     - Creates/updates Lambda function `ai-thumbnail-backend` (512MB RAM, 60s timeout).
     - Provisions Amazon API Gateway HTTP API (`ai-thumbnail-api`) with a `$default`
       proxy route and wildcard CORS enabled.

  3. Errors Encountered & How They Were Resolved:
     - Error: `SignatureDoesNotMatch` on S3 presigned URLs
       * Cause: An inline comment in `.env` (`AWS_REGION=ap-south-1 # (...)`) was
         parsed by dotenv as part of the region string, breaking cryptographic signatures.
       * Fix: Cleaned `.env` to remove the inline comment.
     - Error: `InvalidParameterValueException: Reserved keys used in this request: AWS_REGION, AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY`
       * Cause: AWS Lambda reserves these keys because the Lambda runtime and IAM Execution
         Role automatically inject them into the execution environment.
       * Fix: Removed reserved keys from the Lambda environment variables map, and updated
         `backend/app/storage.py` so boto3 seamlessly uses the Lambda IAM Role credentials.

  4. Live Verification on Cloud:
     - Live Base URL: https://78jpzfhwr4.execute-api.ap-south-1.amazonaws.com
     - Health Check (`GET /`): Status 200 OK (`status: healthy`, `s3_configured: true`).
     - Guardrail (`POST /api/validate`): Status 200 OK (`is_allowed: true`).
     - Supabase History (`GET /api/history`): Status 200 OK.
     - Frontend configured via `frontend/.env` (`VITE_API_BASE_URL`).

     - Amazon S3 can serve static web assets (HTML, CSS, JavaScript, SVGs) directly
       to web browsers without needing an active web server process (like Nginx/Apache).
     - Automatically routes root requests (`/`) to `index.html`.
     - Automatically routes 404s to `index.html` as the Error Document, enabling

  2. Why Cloudflare CDN instead of AWS CloudFront?
     - AWS CloudFront enforces a manual account verification review on newly created accounts
       ("Your account must be verified before you can add new CloudFront resources"), which
       takes 24-48 hours via AWS Basic Support.
     - Cloudflare offers an instant, zero-delay global CDN network with free automated
       SSL/TLS edge certificates, DDoS protection, and HTTP/3 support for custom domains.
     - By pointing Cloudflare's CNAME directly to the Amazon S3 website endpoint, the
       frontend gets instant global edge caching and free HTTPS without any AWS delay.

     - When a visitor navigates to `https://samratdev.fun`, Cloudflare's edge network

     - For `samratdev.fun`, S3 routes requests to an S3 bucket named `samratdev.fun`.
     - For `www.samratdev.fun`, an S3 bucket named `www.samratdev.fun` automatically
       redirects visitors (`HTTP 301 Moved Permanently`) directly to `https://samratdev.fun/`.
     - Cloudflare's SSL/TLS mode set to "Flexible" ensures visitors enjoy green-padlock
       HTTPS security while Cloudflare communicates seamlessly with S3's static website port.

  14. FOUNDATIONAL CLOUD ARCHITECTURE & AWS ORCHESTRATION
================================================================================

  (a) WHAT IS BOTO3 AND HOW DID WE USE IT?
  ────────────────────────────────────────
  Boto3 is the official Amazon Web Services (AWS) SDK for Python.
  It enables Python scripts to programmatically provision, configure, and communicate
  with AWS cloud resources.

  How Boto3 Was Used Across the Project:
  1. Object Storage Operations (`backend/app/storage.py`):
     - `s3 = boto3.client('s3', region_name='ap-south-1')`
     - Validates storage bucket presence using `s3.head_bucket(Bucket=bucket)`.
     - Uploads generated thumbnails via `s3.put_object(Bucket=..., Key=..., Body=...)`.
     - Generates 24-hour cryptographically signed Presigned URLs via
       `s3.generate_presigned_url('get_object', Params=..., ExpiresIn=86400)`.
  2. Serverless Backend Deployment (`backend/deploy_lambda.py`):
     - Uses `boto3.client('iam')` to create the execution role `ai-thumbnail-lambda-role`
       and attach the AWSLambdaBasicExecutionRole managed policy and custom S3 inline policy.
     - Uses `boto3.client('lambda')` to create/update function code (`lambda_package.zip`),
       configure memory (512MB), set 60s timeout, and set environment variables.
     - Uses `boto3.client('apigatewayv2')` to configure the HTTP API, `$default` proxy
       route, Lambda integration, and CORS policies.
  3. Frontend Static Hosting Sync (`frontend/deploy_frontend.py`):
     - Uses `boto3.client('s3')` to configure website hosting on `samratdev.fun`.
     - Recursively uploads files from `frontend/dist/` with explicit Content-Type and
       Cache-Control headers (`max-age=31536000, immutable` on hashed assets).
     - Configures 301 redirection on `www.samratdev.fun` to the apex domain.

  (b) WHAT IS AWS LAMBDA?
  ───────────────────────
  AWS Lambda is an event-driven serverless computing platform.
  - Serverless: No EC2 instances, operating systems, or virtual machines to manage.
  - Scale to Zero: If no users visit the website, compute cost is $0.00.
  - Billing: Pay strictly for execution duration in milliseconds.
  - Cold Starts vs Warm Runs: First invocation spins up a microVM container (~800ms);
    subsequent invocations reuse the container and execute in sub-100ms.
  - Mangum Adapter: Bridges API Gateway JSON event payloads to FastAPI's ASGI interface.

  (c) WHAT IS AMAZON S3?
  ──────────────────────
  Amazon Simple Storage Service (S3) is an industry-leading object storage service
  providing 99.999999999% (11 9's) data durability.
  - Private Bucket (`ai-thumbnails-samrat-1234`): Storage for thumbnail binaries.
    Public access is blocked. Temporary access is granted via 24h Presigned URLs.
  - Website Bucket (`samratdev.fun`): Static website hosting enabled. Serves the
    compiled React single-page application directly to Cloudflare edge proxies.

  (d) WHAT ARE IAM USERS, IAM ROLES, AND IAM POLICIES?
  ────────────────────────────────────────────────────
  - IAM User: Identity created for human developers or external tools. Uses long-term
    access keys (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`) stored in `.env`.
  - IAM Role: Identity assumed dynamically by AWS services (like Lambda). Uses short-term
    STS credentials and is governed by a Trust Policy (`Service: lambda.amazonaws.com`).
  - IAM Policy: JSON document specifying granular permissions. Following Least Privilege:
    * `AWSLambdaBasicExecutionRole`: Write CloudWatch logs.
    * Inline S3 Policy: Only PutObject and GetObject inside `ai-thumbnails-samrat-1234/*`.

  (e) WHY DO WE MAKE A DIST FOLDER?
  ─────────────────────────────────
  When developing in React and Vite:
  1. Browsers cannot parse raw JSX (`<PromptInput />`) or hundreds of unbundled ES modules.
  2. `npm run build` transpiles JSX into universal vanilla JavaScript.
  3. Vite tree-shakes unused libraries, minifies code, and appends unique content hashes
     (e.g., `index-CGRfdZ1B.js`, `index-CMK0pZSs.css`).
  4. Content hashing enables permanent browser caching (`max-age=31536000, immutable`),
     while guaranteeing that any updated build generates a new hash and busts cache instantly.
  5. The resulting `dist/` directory contains pure static files that can be hosted
     directly on Amazon S3 and edge-cached on Cloudflare with zero web server maintenance.

  16. TROUBLESHOOTING & REAL-WORLD ERROR ENCYCLOPEDIA
===============================================================================

  1. CloudFront Account Verification Freeze:
     - Error: `AccessDenied: Your account must be verified before you can add new CloudFront resources`.
     - Cause: AWS freezes CloudFront provisioning on new accounts to prevent CDN spam.
     - Fix: Pivoted to Cloudflare CDN (instant free SSL, global Anycast, zero verification delay).

  2. S3 Custom Domain Host Header 404:
     - Error: `404 Not Found: The specified bucket does not exist`.
     - Cause: S3 static website hosting requires the bucket name to match the incoming `Host` header.
     - Fix: Created S3 bucket `samratdev.fun` and redirect bucket `www.samratdev.fun`.

  3. Windows vs Linux Binary Incompatibility for AWS Lambda:
     - Error: Lambda crashed with missing `.so` C-extensions.
     - Cause: Windows installs `.pyd` DLLs instead of Linux ELF binaries.
     - Fix: In `package_lambda.py`, forced pip to download `manylinux2014_x86_64` wheels.

  4. Presigned URL Signature Mismatch:
     - Error: `SignatureDoesNotMatch: The request signature we calculated does not match`.
     - Cause: Region `ap-south-1` requires Signature Version 4 (`s3v4`) and explicit regional endpoints.
     - Fix: Explicitly set `region_name="ap-south-1"` and `s3v4` addressing in Boto3.

  5. API Gateway CORS Preflight Failure on HTTP DELETE:
     - Error: Browser blocked gallery item deletion due to CORS preflight failure.
     - Cause: API Gateway HTTP API default `AllowMethods` lacked `DELETE`.
     - Fix: Updated API Gateway CORS configuration to include `DELETE` and `OPTIONS`.

  6. FastAPI 422 Missing Form Field on Image Modification:
     - Error: Image-to-image edit displayed `⚠ Field required`.
     - Cause: Parameter `prompt: str` in multipart endpoint was treated as a query parameter.
     - Fix: Typed `prompt: str | None = Form(None)` and added fallback query extraction.

  7. AI Subject Hallucination (Girl holding apple instead of apple):
     - Error: LLM prompt expansion drifted simple subject prompts into human scenes.
     - Cause: Overly narrative prompt engineering system prompts.
     - Fix: Enforced strict system prompt rules preserving user subject verbatim.

  8. Windows PowerShell Execution Policy Restrictions:
     - Error: `.venv\Scripts\Activate.ps1` blocked with `PSSecurityException`.
     - Cause: PowerShell script execution restrictions.
     - Fix: Executed commands directly via `backend\.venv\Scripts\python.exe`.
